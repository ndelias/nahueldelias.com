<BodySection label="The problem" heading="The app looked like it was built by a different team every week.">
  Seven status badges, a dozen hand-built play buttons, prices in three greens, and a fix in one place stayed wrong in ten others. For a product asking labels to trust it with their music, looking unfinished was a real cost.
</BodySection>

<BodySection label="What I did" heading="I designed the system and moved the whole app onto it.">
  I set the visual direction, added tokens for surfaces, shadows, layering and motion, built shared components on them, redesigned Discover and moved the rest of the app across. Then I made it hold, with a design check in CI and a mobile spec built into the components. The team helped build the cards in use today.
</BodySection>

<SystemFigure label="How it works" spec={designSystem} />

<Row label="Color" heading="Color means something." step={1}>
  Dark only, so cover art stands out, lavender for the brand and actions, and green only for money, so the price is always easy to find. Mono type for data like prices, BPM and dates.
</Row>

<Row label="Shared parts" heading="One badge in place of seven." step={3}>
  Every screen builds on the same shared components instead of copying them, like the play button, the price pill and one status badge. One lesson came the hard way. A class defined only in an app's styles silently did nothing in a shared component, which broke the tabs and the carousel, so shared utilities now live in the base config.
</Row>

<Row label="Under the hood · Migration" heading="The whole app moved across in five waves." step={5}>
  The dark-only rebrand, then shared components, then screens, then the smaller apps. Each wave was fixed by hand and checked with searches. Then the CI check turned those searches into a permanent gate, widened area by area as each was cleaned, so the work can't quietly slide back.
</Row>

<Row label="Under the hood · CI" heading="A check in CI keeps every change on the system." step={8}>
  It's a search script, not a lint plugin, so CI needs no extra tools, and it runs on every PR. It fails the build on colors that bypass the tokens, raw layering values, one-off motion, components that turn the focus ring off, and bottom bars outside the shared one. Raw hex only warns, since some is legitimate. Exceptions sit in two lists, permanent with a reason or temporary with a ticket, and if the search itself errors, the build fails. Its first run caught a thinner icon line and a 32px close button.
</Row>

<Row label="Under the hood · Phones" heading="Touch sizes come from the components." step={7}>
  The mobile spec lives in the shared components, so screens get it by default. Tap targets grew to 48px, the mobile chrome first, then Discover, then the rest, each checked in a browser. One shared focus ring serves every interactive component, and below 768px dialogs become real bottom sheets, switched in one place.
</Row>
