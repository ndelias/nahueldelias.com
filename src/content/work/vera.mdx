<BodySection label="The problem" heading="Review didn't slow down. Attention did.">
  In a year, merge requests at GitLab that disclose AI help went from 3% to 22%, and the code in each change doubled, from 37 lines to 76. Time to merge didn't move. Something had to give, and it was attention: review comments per line fell 38%. People are approving changes they haven't really read.
</BodySection>

<Figure src={whyNow} alt="Two charts: merge requests disclosing AI help rising to 22% by month, and lines changed per merge request climbing to 76 while time to merge stays flat." caption="Measured on GitLab's product repo, which is developed in public" />

<BodySection label="Research first" heading="I let the data pick the product.">
  I started with a different idea, Blast Radius. Before building anything, I wrote down how I'd test it, then pulled 78,276 public posts and 105,397 merge requests, and coded 2,000 posts at random. Blast Radius came last. Reviewers drowning in AI-written code came first.

  Every plan was committed before its data, and every number on the site links back to it, including the hypotheses that turned out wrong.
</BodySection>

<Figure src={ranking} alt="Twelve pains ranked by score. AI-written code needing cleanup and overloaded code review tie at the top; non-engineers depending on engineering, my original idea, is last." caption="Twelve pains, scored on the same rules. My first idea is the grey bar at the bottom" />

<BodySection label="The product" heading="Understood, signed off, shipped.">
  Vera sits above the review bots. Four agents read each pull request. One maps what it touches and spots likely AI-written code nobody has checked. One writes a brief for each role. One asks the reviewer a couple of questions to check they understood the change, and records the answer on the approval. One gets design, security and product to sign off at the same time.

  Reviewers can ask Vera about the change. It answers from the code, with the lines it used, but it won't hand out the answers to an open check. And rules in the repo, not a model, decide who has to approve.
</BodySection>
