The design tokens are in: color for both themes, the type scale, a 4px spacing scale and a 12-column grid, all as CSS custom properties in one file.

- **Each color is one `light-dark()` pair.** Light is the default, dark follows the system, and a saved choice overrides the system in either direction. A one-line script in the `<head>` applies the saved choice before first paint, so there's no flash of the wrong theme. It's the only JavaScript on `/`: 0.1KB.
- **Contrast is a test, not a promise.** It reads the token file, computes every text/background pair in both themes, and fails below WCAG AA. The tightest pair is muted text on a surface in light, at 4.72:1. I lightened the muted color until the test went red, and it did.
- **Fonts are self-hosted.** Instrument Sans 400/500 and DM Mono 400, Latin subset: 48.9KB for all three. Each page preloads only the faces it uses above the fold. The placeholder `/` never downloads the mono.
- **The font swap keeps every line's height.** Until a webfont arrives, text sets in a local Arial or Courier New scaled to the webfont's average width, with the webfont's ascent and descent. A small script reads those numbers from the font files themselves. Line heights match exactly, so text never pushes the content below it down. Line breaks match unless a line ends within about 2% of its box: Arial and Instrument Sans only match on average. Across 141 viewport widths, `/` never reflowed.
- **The three largest sizes are fluid.** Display runs from 40px on a 320px screen to 72px at 1440px, h2 from 30 to 44, and the homepage's focused title from 28 to 40. The other steps stay fixed.
- **The arrows and the dot are SVG.** The subset fonts don't include ← → ↗ ●, so a small icon component draws them in the text color at the text's size.

LCP on `/` went from 0.75s to 1.05s, against a 1.2s budget. It's a paragraph of text, so it has nothing to load. The time is 451ms to the first byte and 601ms of render delay. Swapping the webfonts for system fonts cuts the render delay to 301ms, so the fonts account for the 300ms. With or without preloads, the number is the same. But that cost only exists in the simulation the budget uses. Lighthouse models slow 4G from a fast unthrottled load, where the fonts arrived before the text first painted, so it counts them as something the text waits for. On an actually throttled connection the text paints at 0.71s in the fallback, and the fonts arrive at 1.33s. The gate is what it is, though. The real homepage has 150ms to spend.

A side effect: the CSS crossed Astro's 4KB inline limit and became a separate stylesheet, a render-blocking round trip in front of LCP. All CSS is now inlined.

`/_tokens` shows every token in both themes side by side, for checking against the design. It isn't indexed or linked from anywhere.
